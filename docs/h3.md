# H3 primer (for ÐMaps and ÐLand)

[H3](https://h3geo.org/) is Uber's hexagonal hierarchical spatial index. The earth (and, with a different projection, other bodies) is tiled by hexagons. Every hexagon has a compact 64-bit index, written as a lowercase hexadecimal string (usually 15 digits, starting with `8` for a cell). A finer resolution subdivides each hexagon into seven children. Uber releases the library as Apache-2.0.

This repo pins **H3 C library v4.2.1** (the `h3-js` 4.2.1 binding is the JavaScript reference). See [INDEXING.md](INDEXING.md) and ÐMaps [spec.md §7.5](../protocols/dogemaps/spec.md#75-h3-library-pin-and-official-test-cells-must).

## Why hexagons

Neighbors are uniform (up to a handful of pentagons needed to close the sphere). You can roll a fine pin up to a neighborhood or a city by taking the **parent** cell, and you can ask for the adjacent pins with `gridDisk`. That is the whole geometry ÐMaps and ÐLand need.

## Resolutions (official average sizes)

Values are Uber's published averages for Earth.

| Res | Avg edge | Avg area | Role in this stack |
| ---: | --- | --- | --- |
| 0 | 1,108 km | 4,357,449 km² | — |
| 3 | 59.8 km | 12,393 km² | Optional coarser region rollup (display) |
| 4 | 22.6 km | 1,770 km² | **ÐLand Region** |
| 7 | 1.22 km | 5.16 km² | **ÐLand District** (Founder badge lives here) |
| 8 | 461 m | 0.74 km² | ÐMaps derived overlay MAY use 8 (official test: height 12345) |
| 9 | 174 m | 0.105 km² | **ÐMaps default derived overlay** (`H3_RES = 9`) |
| 11 | 24.9 m | 2,150 m² | Too coarse for a shop pin |
| 12 | 9.42 m | 307 m² | **ÐLand anchor pin** (findable, not a doorstep GNSS trace) |
| 13 | 3.56 m | 44 m² | Inside typical phone-GPS noise; not used |

## Two different cells (do not mix them)

**Derived overlay (ÐMaps).** Every block height hashes to a latitude/longitude, then to an H3 cell at resolution 9 (by default). Nobody chooses it. Two indexers MUST get the same cell (official table in the ÐMaps spec). This is a *deterministic world map of titles*, useful for a globe, not a claim to a street address.

**Chosen pin (ÐLand `anchor`).** The current title holder spends the title and commits a resolution-**12** cell they picked ("use my location", a search result, a ÐGPS place). Each res-12 cell has at most one occupant, settled by commit-first. That pin rolls up:

```
pin (res 12)  →  parent res 7 = District  →  parent res 4 = Region
```

Parents are defined by the H3 bit layout (set the resolution field, set finer digits to the unused value 7). The codec in this repo implements `h3Parent` without calling a library; it MUST match H3 4.2.1 `cellToParent`.

## Latitude / longitude → cell

```js
import { latLngToCell, cellToLatLng, cellToParent, gridDisk } from "h3-js"; // 4.2.1

// Chosen pin (ÐLand): snap a WGS-84 point to res 12
const pin = latLngToCell(37.812, -122.478, 12);
const [lat, lng] = cellToLatLng(pin);
const district = cellToParent(pin, 7);
const region = cellToParent(pin, 4);
const neighbors = gridDisk(pin, 1); // includes self; drop pin for "other parcels"

// Derived overlay (ÐMaps): do NOT pass a geocoded point.
// Hash the block height as in protocols/dogemaps/spec.md §7, then:
// import { seedLatLng } from "../reference/dmaps-geo.mjs";
// const { lat, lng } = seedLatLng(0, 9);
// const overlay = latLngToCell(lat, lng, 9); // MUST be 89e98d184b7ffff
```

`latLngToCell` must be called with the IEEE-754 float64 values from §7.3, not a rounded decimal string.

## One-tap pin (product)

1. The user holds a parcel title.
2. "Use my location" or search a place.
3. Snap to res 12. Ask the indexer `GET /api/land/cell/{h3}` — free, occupied, or pending.
4. Show the district, whether this would make them Founder, and any re-anchor cooldown.
5. Commit, wait one confirmation, reveal — spending the title UTXO in the reveal (ÐLand §6).

An anchor is **not** legal property. GPS can be spoofed. See ÐLand §9.7.
